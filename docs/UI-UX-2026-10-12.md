# SYY-Shop — UI/UX 15 รายการ

## 1. สรุปผลการตรวจสอบ

ดำเนินการตามคำสั่ง “ดำเนินการแก้ไขทั้งหมดเลย” สำหรับ UI/UX 15 รายการที่วิเคราะห์ก่อนหน้า บน branch `codex/integrity-security-20261011` ต่อจาก baseline `ff44c3560f8c6d9116b21383a9ac229bb5aad341` ตรวจ Source/Git และ Master Instructions ก่อนแก้ไข ไม่ย้อนกลับงาน integrity/security 1–40

แก้ implementation ทั้ง 15 ด้านแล้ว ผลยืนยันมาจาก Source, local Firestore fixtures และ Chrome ที่ปิด external HTTPS การตรวจนี้ไม่ใช่ live UAT หรือหลักฐาน performance/billing ของ Production

## 3. ผลกระทบ

Quotation, StockIssue, Tax Invoice, Purchase Orders และ Product form ใช้ draft adapters เฉพาะข้อมูลธุรกิจร่วมกับ helper กลาง ไม่เก็บ password, auth/reset token, OTP, TOTP secret หรือ recovery codes เมตาดาต้าบัญชี/role มาจาก authenticated server template ไม่ใช้ local state ตัดสินสิทธิ์ backend

ไม่เปลี่ยน collections/schema, stock/movement/receipt atomic commits, document numbering, role policy, API names หรือ pricing rules รายการสต๊อกที่ไม่ทราบผลยังใช้ request ID เดิม และเก็บแยกจากร่างธรรมดา แม้ออกจากระบบ เพื่อป้องกันตัดซ้ำ

การค้นหา PO โหลดเฉพาะ vendor ที่อ้างอิงเมื่อ cache เย็น และไม่ดึง low-stock/pending summary ซ้ำ ส่วน bootstrap ยังสร้าง pending summary ครบช่วงตามเดิม

## 4. แนวทางแก้ไข

ใช้ Shared/Styles/XLF และ page adapters ในโครงสร้างเดิม ไม่มี framework หรือ service ใหม่ การค้นเลขเอกสารเป็น exact match; filters คอลัมน์/สถานะยังกรองข้อมูลที่โหลดเท่านั้นและมีคำอธิบายชัดเจน

Date-only query ใช้ date ordering เดิม Exact-number query ใช้ single-field equality และ name ordering แล้วตรวจวันที่ภายในแต่ละหน้าที่จำกัดขนาด วิธีนี้ไม่เพิ่ม composite index/backfill ใหม่ Cursor ตรวจ collection/project/year/search/readTime และไม่ปะปน snapshot

Server paging เริ่ม 50 rows และโหลดเพิ่มสูงสุด 200 ส่วน display paging 50 rows ไม่เรียก Firestore เพิ่ม Load All ยังคงเป็นการกระทำของผู้ใช้ สำหรับสรุปทั้งช่วงต้องโหลดครบและล้างเงื่อนไขค้นหาก่อนสรุปรายปี

## 5. ความเสี่ยง

- ร่างอยู่เฉพาะ browser session/origin/บัญชี/role เดิม อายุ 8 ชั่วโมง ขนาด record จำกัด 500,000 characters เมื่อ storage ไม่พร้อมหรือร่างรูปใหญ่เกินขนาดจะแจ้งเตือนให้เก็บหน้าไว้ ไม่อ้างว่าเก็บสำเร็จ
- Draft recovery ไม่ใช่การสำรองข้อมูลถาวร ต้องตรวจค่าปัจจุบันก่อนบันทึก Stock baseline และ image updateTime เดิมถูกคงไว้ เพื่อให้ backend ตรวจ conflict ตามเดิม
- Quote/Invoice/PO และการสร้าง Product ที่ไม่ทราบผลจาก transport failure ถูกล็อกส่งซ้ำ ผู้ใช้ต้องตรวจทะเบียนก่อนทิ้งร่าง/สร้างใหม่ ไม่เพิ่ม backend idempotency protocol ใหม่ให้เอกสารเหล่านี้
- ต้องตรวจ default index exemptions, GAS iframe/history/sessionStorage partitioning, top navigation, browser fonts และ PDF libraries บน Staging จริง การเปลี่ยน deployment/origin อาจทำให้ไม่พบร่างจาก origin เดิม
- การทดสอบชื่อไทยยาวหลายหน้าไม่ใช่การรับรอง printer/font/เอกสารผิดปกติทุกชนิด ต้องตรวจ PDF และกระดาษตัวอย่างจากเครื่องใช้งานจริง

## 8. ผลกระทบต่อ Firestore

ไม่มีการอ่าน/เขียน/ลบ Firestore จริงในงานนี้ ไม่มี schema/index/rules/IAM migration และไม่เพิ่ม Firestore business writes จาก UI helpers Draft/view persistence ใช้ browser storage เท่านั้น

การเปลี่ยน display page, กู้คืนร่าง และ CSV ไม่เพิ่ม server reads การค้นหาต้องมี bounded query ตามการกดค้น/โหลดเพิ่ม Exact Invoice/Quote fixture 1,500 documents พบเอกสารเป้าหมายด้วย 1 query/1 document result และไม่มี collection scan ส่วน PO cold search เพิ่มเฉพาะ GET vendor ที่อ้างอิง 1 รายการแทนอ่าน vendor 1,001 รายการ

Pagination มี lookahead 1 document ต่อขอบหน้าเหมือนเดิม การโหลดทั้งหมดไม่ใช่การประหยัด reads เสมอ และ document results ไม่เท่ากับ billed reads/index-entry reads เปอร์เซ็นต์ savings รวมระบบและ p50/p95 latency ยังสรุปไม่ได้จนวัด workload จริงที่จับคู่ baseline บน Staging

## 9. Git Commit และ Deployment

Implementation SHA คือ commit ที่เพิ่มรายงานนี้ ตรวจด้วย `git log -1 --format=%H -- docs/UI-UX-2026-10-12.md` และ SHA ในข้อความส่งมอบ Baseline `ff44c3560f8c6d9116b21383a9ac229bb5aad341`

Local commit บน `codex/integrity-security-20261011` ไม่มี public push/PR ใหม่/merge, Apps Script sync หรือ deployment และไม่แตะข้อมูล/สิทธิ์ Production Public PR #2 ของ branch daily backlog เป็นงานก่อนหน้า ไม่ใช่ revision นี้ เตรียม review package จาก committed source พร้อม checksums; review package ยังมี Source Project ID จึงต้องใช้ staging override เมื่อตรวจ live writes

## 10. งานคงเหลือ

Implementation 15 ด้านและ local regressions เสร็จ งานที่ยังต้องยืนยันคือ Staging UAT กับ Apps Script/Firestore target แยก, roles/sessions หลายบัญชี, real index/query costs, network latency, storage/navigation ใน GAS iframe, fonts/PDF/export และ printer ใช้ runbook `docs/STAGING-UAT-2026-10-12.md` โดยเพิ่มกรณี UX ในรายงานนี้ก่อนอนุมัติ Production rollout

ยังไม่มี Staging ID/URL/project/mailbox ใน workspace จึงไม่ deploy หรือถือว่าการทดสอบ local ปิดงาน live ที่ค้างอยู่ ต้อง rollout client/backend จาก revision เดียวกันตาม scope ที่ได้รับอนุมัติ

อ้างอิงวิธี history บน GAS iframe จาก [Google Apps Script history API](https://developers.google.com/apps-script/guides/html/reference/history) โดยคง URL parameters เดิมและเก็บ state เฉพาะชื่อเมนู ไม่มี token ใน history state/local storage
